# RentNote 数据持久化方案

## Goal

将 PropertyRepository 从内存 Mock 迁移到鸿蒙 RdbStore 关系型数据库，应用重启后数据不丢失。

## Scope / Non-goals

**包含：**
- `property` 表的 RdbStore 建表与完整 CRUD
- `tags: string[]` 字段以 JSON 字符串存储
- Context 从 EntryAbility 注入
- 首次安装插入示例数据
- Repository 写操作改 async + 内存数组刷新
- ViewModel / Page 层最小化适配

**不包含：**
- 数据导入/导出页面改造
- Widget 卡片数据源改造
- 数据库加密（S1 足够）
- 数据库版本迁移机制

## 需要持久化的数据

项目当前只有一个业务实体 `PropertyInfo`，其所有字段都必须持久化：

| PropertyInfo 字段 | RDB 列名 | 数据类型 | 约束 | 说明 |
|---|---|---|---|---|
| id | id | TEXT | PRIMARY KEY | 房源 ID（时间戳字符串） |
| name | name | TEXT | NOT NULL | 小区名 |
| address | address | TEXT | DEFAULT '' | 详细地址 |
| district | district | TEXT | DEFAULT '' | 区域 |
| tags | tags | TEXT | DEFAULT '[]' | **JSON 字符串**，如 `'["近地铁","精装修"]'` |
| monthlyRent | monthly_rent | INTEGER | DEFAULT 0 | 月租金 |
| deposit | deposit | INTEGER | DEFAULT 0 | 押金 |
| startDate | start_date | TEXT | DEFAULT '' | 入住日期，格式 `2024.03.01` |
| endDate | end_date | TEXT | DEFAULT '' | 到期日期 |
| status | status | TEXT | DEFAULT 'candidate' | `renting` / `expiring` / `candidate` |
| billsPaid | bills_paid | INTEGER | DEFAULT 0 | 已缴账单数 |
| imageUrl | image_url | TEXT | DEFAULT '' | 图片 URL |
| notes | notes | TEXT | DEFAULT '' | 备注 |
| renewalStatus | renewal_status | TEXT | DEFAULT '' | `renew` / `no_renew` / `undecided` / `''` |

**无需单独建表的派生数据：**
- `StatisticsOverview`、`MonthlyRentItem`、`LeaseTimelineItem` — 均由 PropertyInfo 数组实时计算得出，无需持久化
- `PropertyIdParam`、`SaveResult`、`DeleteResult` — 路由参数/返回值，不存储

**总表数：1 张**（`property` 表）

## Current State And Constraints

| 现状 | 约束 |
|---|---|
| PropertyRepository 纯内存 + Mock 数据 | 改为 RdbStore 持久化 |
| 所有 Repository 方法同步 | RdbStore API 全异步（Promise），写操作必须 async |
| ViewModel.loadData() 同步 | 改为 async |
| 无 Context 传递 | getRdbStore(context, config) 需要 Context |
| tags: string[] | RdbStore 无数组类型，用 JSON.stringify/parse |
| @Trace properties[] 驱动 UI | 保留此模式，查询后赋值即可 |
| ArkTS 禁止 `obj['key']` 动态属性访问 | 读取 ResultSet 用 getString/getLong + getColumnIndex；写入用 ValuesBucket 对象字面量 |

## Design

### 1. RdbStore 数据库配置

使用 `@kit.ArkData` 中的 `relationalStore` 模块：

```typescript
import { relationalStore } from '@kit.ArkData';

const STORE_CONFIG: relationalStore.StoreConfig = {
  name: 'RentNote.db',
  securityLevel: relationalStore.SecurityLevel.S1
};

const CREATE_TABLE_SQL: string =
  'CREATE TABLE IF NOT EXISTS property (' +
  'id TEXT PRIMARY KEY, ' +
  'name TEXT NOT NULL, ' +
  'address TEXT DEFAULT \'\', ' +
  'district TEXT DEFAULT \'\', ' +
  'tags TEXT DEFAULT \'[]\', ' +
  'monthly_rent INTEGER DEFAULT 0, ' +
  'deposit INTEGER DEFAULT 0, ' +
  'start_date TEXT DEFAULT \'\', ' +
  'end_date TEXT DEFAULT \'\', ' +
  'status TEXT DEFAULT \'candidate\', ' +
  'bills_paid INTEGER DEFAULT 0, ' +
  'image_url TEXT DEFAULT \'\', ' +
  'notes TEXT DEFAULT \'\', ' +
  'renewal_status TEXT DEFAULT \'\' )';
```

### 2. Context 注入

在 `EntryAbility.onCreate()` 中将应用 Context 存入 AppStorageV2：

import { AppStorageV2 } from '@kit.ArkUI';

onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {

### 3. PropertyRepository 改造

**架构：保留 `@Trace properties: PropertyInfo[]` 内存数组驱动 UI**

```
┌────────────────────┐    async write    ┌──────────────┐
│  RdbStore (持久化磁盘) │ ────────────────> │ properties[] │ ──> @Trace 驱动 UI
│                      │ <──────────────── │  (内存缓存)   │
└──────────────────────┘    refreshFromDb   └──────────────┘
```

**方法变更清单：**

| 方法 | 变更前 | 变更后 |
|---|---|---|
| `constructor()` | 生成 Mock 数据 | 空构造，不初始化 RdbStore |
| `init(context)` | 不存在 | **新增** async：getRdbStore → executeSql 建表 → 查全表填充 properties[] → 首次插入示例数据 |
| `addProperty(p)` | 同步，push 数组 | async：store.insert → refreshFromDb() |
| `updateProperty(p)` | 同步，替换数组项 | async：store.update → refreshFromDb() |
| `deleteProperty(id)` | 同步，filter 数组 | async：store.delete → refreshFromDb() |
| `promoteCandidate(id)` | 同步，改 status | async：store.update status → refreshFromDb() |
| `refreshFromDb()` | 不存在 | **新增** async 私有：store.query 全表 → 赋值 properties[] |
| 其他查询方法 | 同步 | **不变**，仍从内存 properties[] 过滤 |

**refreshFromDb 核心实现（ArkTS 合规的 ResultSet 读取模式）：**

```typescript
private async refreshFromDb(): Promise<void> {
  const predicates = new relationalStore.RdbPredicates('property');
  predicates.orderByAsc('id');
  const resultSet = await this.store!.query(predicates);
  const list: PropertyInfo[] = [];
  while (resultSet.goToNextRow()) {
    const p = new PropertyInfo();
    p.id = resultSet.getString(resultSet.getColumnIndex('id'));
    p.name = resultSet.getString(resultSet.getColumnIndex('name'));
    p.address = resultSet.getString(resultSet.getColumnIndex('address'));
    p.district = resultSet.getString(resultSet.getColumnIndex('district'));
    const tagsStr = resultSet.getString(resultSet.getColumnIndex('tags'));
    p.tags = JSON.parse(tagsStr) as string[];
    p.monthlyRent = resultSet.getLong(resultSet.getColumnIndex('monthly_rent'));
    p.deposit = resultSet.getLong(resultSet.getColumnIndex('deposit'));
    p.startDate = resultSet.getString(resultSet.getColumnIndex('start_date'));
    p.endDate = resultSet.getString(resultSet.getColumnIndex('end_date'));
    p.status = resultSet.getString(resultSet.getColumnIndex('status'));
    p.billsPaid = resultSet.getLong(resultSet.getColumnIndex('bills_paid'));
    p.imageUrl = resultSet.getString(resultSet.getColumnIndex('image_url'));
    p.notes = resultSet.getString(resultSet.getColumnIndex('notes'));
    p.renewalStatus = resultSet.getString(resultSet.getColumnIndex('renewal_status'));
    list.push(p);
  }
  resultSet.close();
  this.properties = list;
}
```

**ValuesBucket 写入模式（ArkTS 合规）：**

```typescript
const values: relationalStore.ValuesBucket = {
  'id': p.id,
  'name': p.name,
  'address': p.address,
  'district': p.district,
  'tags': JSON.stringify(p.tags),
  'monthly_rent': p.monthlyRent,
  'deposit': p.deposit,
  'start_date': p.startDate,
  'end_date': p.endDate,
  'status': p.status,
  'bills_paid': p.billsPaid,
  'image_url': p.imageUrl,
  'notes': p.notes,
  'renewal_status': p.renewalStatus,
};
```

### 4. 首次安装示例数据

`init()` 中建表后执行 `SELECT COUNT(*) FROM property`，若为 0 则 `batchInsert` 5 条预置数据（复用现有 Mock 数据内容）。

### 5. ViewModel 层适配

| ViewModel | 变更 |
|---|---|
| HomeViewModel | `loadData()` → async，调用 `await repository.reloadData()` |
| StatisticsViewModel | `loadData()` → async |
| AddPropertyViewModel | `saveProperty()` → async；`deleteProperty()` → async |
| PropertyDetailViewModel | `loadProperty()` → async；`deleteProperty()` → async |

Repository 新增 `reloadData()` async 方法供 ViewModel 调用（等价于 refreshFromDb + 后续计算逻辑）。

### 6. Page 层适配

`aboutToAppear()` 不能是 async，但可以调用 async 方法（fire-and-forget），@Trace 会在数据赋值后自动刷新 UI：

```typescript
aboutToAppear(): void {
  this.viewModel.loadData(); // 返回 Promise，不 await，@Trace 自动刷新
}
```

**AddPropertyPage 保存按钮 onClick 中**：`saveProperty()` 改 async 后，onClick 中直接调用即可。

### 7. Index.ets 初始化

```typescript
aboutToAppear(): void {
  const context = AppStorageV2.connect<Context>('appContext')!;
  this.repository.init(context); // async，fire-and-forget
}
```

## Risks And Compatibility

| 风险 | 缓解 |
|---|---|
| RdbStore 初始化时序 — 首帧渲染时数据未就绪 | @Trace properties[] 初始为空，UI 显示空态；init() 完成后 @Trace 自动刷新 |
| `JSON.parse` 在 ArkTS 中受限 | 标准库 JSON.parse/stringify 在 ArkTS 中可用，`as string[]` 断言对系统 API 返回值是允许的 |
| `ValuesBucket` 是 `Record<string, ValueType>` 类型 | 创建时用对象字面量 + 显式类型注解（合规）；读取时用 ResultSet.getString/getLong（合规） |
| batchInsert 参数上限 32766 | 5 条示例数据远低于上限 |

## Rollback

若 RdbStore 持久化导致严重问题：
1. git checkout 恢复 PropertyRepository.ets 为内存实现
2. 恢复 ViewModel 同步方法签名
3. 恢复 Page 中同步调用
4. 移除 EntryAbility Context 注入
